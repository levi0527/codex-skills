# 技术解决方案 PPT 方法论

这套方法论来自 G1 人形机器人垒球抛接球闭环方案汇报。适用于“了解客户需求后，向领导汇报技术解决方案”的 PPT。

## 核心叙事顺序

不要直接从方案模块开始。领导首先需要相信团队理解了客户场景，再看方案是否合理。

推荐顺序：

1. 场景或运动本身的特点
2. 这些特点带来的工程难点
3. 难点到功能设计的映射
4. 总体逻辑框图
5. 分模块解释方案
6. 异常流程和兜底方案
7. 时间线和验收口径
8. 近期决策事项

对于垒球类方案，可按这个逻辑表达：

- 垒球不是“抓一个球”，而是高速飞行、动态接触、稳定持球释放和连续回合。
- 来球方向变化要求视觉预测和在线修正。
- 接触冲击要求手套 pocket、末端顺应和接球稳定判断。
- 右手 release timing 要稳定，要求掌中球位固定。
- 连续 demo 要求 ball transfer 和失败兜底。

## 页型建议

### 1. 场景特点页

目的：告诉领导“我们理解客户需求的根源”。

结构：

- 一个短标题说明场景难点
- 3-4 个特点卡片
- 每个特点只写一句工程含义
- 底部用一句话总结方案设计围绕哪些能力展开

示例：

- 来球方向变化：接球动作必须在线调整
- 接触冲击明显：需要 pocket 容错和末端顺应
- 持球姿态稳定：否则 release timing 很难稳定
- 回合必须连续：失败后也要回到下一次抛球

### 2. 功能映射页

目的：把客户问题自然翻译成工程功能。

不要写“领导关注点”。改成“由场景特点到功能设计”。

示例映射：

- 多方向来球：ZED-X + EKF 预测 `p_hit / t_hit`
- 接触冲击：成熟手套 + G1 wrist mount 顺应结构
- 连续回合：Fixed Transfer Zone + ball-box recovery

### 3. 总体逻辑框图

目的：让领导先看到闭环。

推荐画法：

`右手抛球 -> 球路飞行 -> 视觉预测 -> 左手接球 -> 固定转移区 -> 右手抓取 -> 再抛`

另加一条失败路径：

`接球失败 -> 球框取球 -> 硬编码恢复 -> 再抛`

框图要比文字早出现。框图之后再解释每个模块为什么存在。

### 4. 方案解释页

每页只回答一个问题：

- 接球能力优化：怎么验证多方向来球和手套适配
- 右手抛球：怎么从 Motion Tracking 到 release control
- Ball Transfer：为什么不做空中递球，而用胸前固定球位
- 异常兜底：失败后如何保证 demo 不断

标题要直接，不要写口号。正文少写抽象词，多写动作、接口、条件和验收物。

### 5. 示意图页

图示优先级：

1. 用户提供的好图，优先保留并放大
2. 生成或搜索概念图作为底图
3. 在 PPT 中用可编辑文字标注解释关键点
4. 对复杂图拆成两页，不要缩成一页

Ball Transfer 适合使用 G1 上半身示意图：

- 左手手套把球稳定在胸前
- 蓝色半透明区域表示固定转移区
- 右手靠近同一球位
- 图内不要带文字，文字在 PPT 中可编辑添加

### 6. 时间线页

时间线不能只有日期和一句话。领导需要看到每个节点能验收什么。

推荐列：

- 节点
- 目标
- 本阶段完成动作
- 验收物

验收物要具体：

- 视频
- 参数
- 状态切换日志
- 失败样例清单
- 演示 SOP
- 下一阶段优化清单

示例节点：

- 2026.09.25：接球能力验证
- 2026.10.30：动作链路打通
- 2026.11.30：闭环演示与兜底
- 并行工作：降低后续风险

## 写作规则

- 用“因为场景要求 A，所以方案采用 B”的因果链。
- 每页只保留一个主问题。
- 少用“打造、赋能、体系化、智能化闭环”等空话。
- 保留必要英文技术词，如 `Motion Tracking`、`WBC`、`RL Residual`、`release condition`，但不要让英文淹没中文逻辑。
- 不要把所有信息塞进表格。先图后表，先逻辑后细节。
- 避免孤立标点换行，中文句子能短就短。

## 视觉规则

- 沿用模板的深蓝页眉和白底。
- 用绿色表示接球或成功路径，蓝色表示主流程，金色表示 release / benchmark，红色表示异常或失败路径，紫色表示算法预测或 residual。
- 卡片和流程框要少而准，尽量保持 3-6 个关键节点。
- 表格只用于方案对比或时间线验收，不要把第一页做成表格。
- 生成图片时尽量无文字、无 logo、无水印，保证 PPT 中的文字可编辑。

## 交付检查

交付前必须：

- 导入模板并确认尺寸。
- 导出 PPTX 后做结构校验。
- 渲染每页或总览图检查视觉。
- 单独检查新增图示页、时间线页和表格页。
- 确认输出文件在当前任务的 `outputs` 目录中。

如果使用外部事实或来源，在备注中保留来源线索。不要把未核实的采购链接写成确定推荐。
